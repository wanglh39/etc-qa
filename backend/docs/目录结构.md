## 两条链路对应的代码调用关系

### 链路1：检索流程（/api/v1/query）

```
routes.py: query_qa()
  → rag/service.py: QAService.query()
      → db/mysql_client.py: get_active_ids()（TTL缓存30s，软删除时主动失效）
      → agent/graph.py: preprocess_agent（2步）
          → processors/clean_text.py（业务清洗规则从config_center读取）
          → processors/standardize_query.py（关键词/正则/阈值从config_center读取）
      → rag/recall.py: RecallEngine.recall()（双路召回+RRF，active_qa_ids过滤两路，@traceable）
      → rag/reranker.py: Reranker.rerank()（从MySQL实时查question文本，@traceable）
      → rag/threshold.py: ThresholdJudge.filter_candidates()（阈值判定）
      → db/mysql_client.py（查完整记录，only_active=True）
  → [未命中] api/work_order/client.py: create_work_order()
  → [未命中] db/mysql_client.py: insert_work_order()
```

### 链路2：入库预处理流程（/api/v1/agent/process）

```
routes.py: agent_process()
  → agent/graph.py: ingest_agent（3步）
      → processors/clean_text.py
      → processors/structure_ingest.py
          → agent/prompt_engine.py（jinja2渲染提示词，DB模板优先→fallback）
          → agent/llm.py: get_structured_llm()（StructuredOutput优先，降级JSON解析）
          → agent/output_schemas.py: StructureIngestOutput（category_confidence+Pydantic校验）
          → 低置信度 → needs_review=True（触发人工审核）
      → processors/hyde_rewrite.py
          → _judge_need_rewrite()（规则预判→LLM判断，两层跳过不需要改写的问题）
          → agent/prompt_engine.py + agent/llm.py: get_structured_llm()
```

### 链路3：知识管理流程

```
PUT /api/v1/qa/status → db/mysql_client.py: update_qa_status() → service.invalidate_active_ids_cache()
GET /api/v1/qa/list → db/mysql_client.py: get_qa_list()（分页+分类/状态过滤）
GET /api/v1/qa/{id} → db/mysql_client.py: get_qa_detail()
DELETE /api/v1/qa/{id} → db/mysql_client.py: delete_qa() → service.invalidate_active_ids_cache()
POST /api/v1/qa/search → db/mysql_client.py: search_qa()（LIKE匹配question/answer）
GET /api/v1/stats → db/mysql_client.py: count_qa() + count_work_orders() + get_category_stats()
GET /api/v1/categories → db/mysql_client.py: get_category_tree()
GET /api/v1/work_orders → db/mysql_client.py: get_work_order_list()
PUT /api/v1/config/{key} → db/mysql_client.py: set_config() → config_center.invalidate_cache()
GET /api/v1/config/{key} → config_center.get_business_config()
POST /api/v1/config/reload → config_center.invalidate_cache()（全量刷新）
```

### 链路4：工单闭环流程（scripts/）

```
scripts/pipeline/ingest_pipeline.py  # 统一入库流水线（6步端到端）
  → agent/processors/clean_text.py
  → agent/processors/structure_ingest.py → agent/llm.py
  → rag/recall.py（去重检索）
  → db/mysql_client.py: insert_qa()
  → db/milvus_client.py: insert()
  → agent/processors/hyde_rewrite.py → agent/llm.py

scripts/data/sync_work_orders.py
  → api/work_order/client.py: fetch_processed_work_orders()
  → db/mysql_client.py: update_work_order() / delete_work_orders_by_status()
  → agent/graph.py: ingest_agent

scripts/maintenance/weekly_dedup.py
  → db/mysql_client.py: get_work_orders_by_status()
  → db/milvus_client.py: search()（第一轮，is_hyde过滤，阈值从config读取）
  → numpy余弦相似度（第二轮）
  → db/mysql_client.py: update_work_order()

scripts/data/batch_import.py
  → db/mysql_client.py: get_work_orders_by_status("deduped")
  → db/mysql_client.py: insert_qa()
  → db/milvus_client.py: insert()（原始+HyDE向量）
  → agent/processors/hyde_rewrite.py
  → 一致性校验（MySQL vs Milvus）

scripts/pipeline/hyde_generate.py
  → db/mysql_client.py（读取qa_pairs）
  → agent/llm.py（生成HyDE假设性问题）
  → Embedding编码 → output/hyde_cache.json

scripts/pipeline/hyde_insert.py
  → 读取output/hyde_cache.json → db/milvus_client.py: insert()（is_hyde=true向量）
  → 每批后关连接+延时3秒（避免gRPC too_many_pings）
```

### 链路5：评估流程（scripts/eval/）

```
scripts/eval/eval_rag.py              # 主评估：4配置消融对比+R@1/3/5/10/MRR+失败分析 → output/
scripts/eval/eval_asr.py              # ASR端到端：CER+纠错+RAG Recall@1 → output/
scripts/eval/eval_structure_ingest.py # 入库改写质量评估 → output/
scripts/eval/eval_prompt_diff.py      # 黄金数据集评估+DIFF对比 → output/
scripts/eval/eval_langsmith.py        # LangSmith evaluate API（自动降级本地）
```

### 链路6：提示词迭代流水线

```
scripts/pipeline/prompt_pipeline.py  # 一键流水线CLI
  iterate: 评估基线 -> 发布新版本 -> 评估新版 -> DIFF对比 -> 建议
  publish:  发布新提示词版本（自动递增版本号，旧版标记inactive）
  rollback: 回滚到指定版本（一键恢复+缓存刷新）
  eval:     运行黄金数据集评估（4个流水线x25条用例）
  diff:     对比两个评估结果JSON（回退/改善/新增/丢失）
  shadow:   启动/停止/查看影子测试

prompt/version_manager.py
  -> db/mysql_client.py（prompt_templates表CRUD）
  -> agent/prompt_engine.py: invalidate_cache()（发布/回滚后刷新缓存）
  -> config_center: invalidate_cache()

prompt/shadow_recorder.py
  -> 内存缓存（_shadow_records，最多10000条）
  -> db/mysql_client.py（shadow_test_log表持久化）

agent/prompt_engine.py（影子测试支持）
  -> render()时检查_shadow_enabled
  -> 若有影子版本 -> 同时渲染 -> record_shadow()记录差异
  -> 不影响主流程返回值
```
