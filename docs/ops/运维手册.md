# 运维手册

## 一、系统监控

### 1.1 组件健康检查

**接口**：`GET /api/system/status`（权限：superadmin, ops）

```json
{
  "api": "ok",
  "mysql": "ok",
  "milvus": "ok",
  "rag": "ok",
  "asr": "ok",
  "scheduler": "running",
  "alert": "ok"
}
```

**前端页面**：/workbench/admin/status（系统状态总览）

### 1.2 性能监控

**接口**：`GET /api/alerts/metrics`（权限：admin, superadmin, ops）

**监控指标**（内存滑动窗口 10 分钟）：

| 指标 | 说明 | 告警阈值 |
|------|------|---------|
| RAG 查询失败率 | RAG 检索失败次数/总次数 | > 10% |
| RAG P95 延迟 | RAG 检索 95 分位延迟 | > 3s |
| LLM 调用失败率 | DeepSeek API 失败次数/总次数 | > 15% |
| Milvus 失败率 | Milvus 操作失败次数/总次数 | > 5% |
| MySQL 失败率 | MySQL 操作失败次数/总次数 | > 5% |
| 任务连续失败 | 定时任务连续失败次数 | >= 3 |

**前端页面**：/workbench/admin/monitor（性能监控看板）

### 1.3 应用日志

**接口**：`GET /api/system/logs?lines=100&level=ERROR`（权限：superadmin, ops）

**日志文件**：`backend/logs/etc_qa.log`（10MB 轮转，5 个备份）

## 二、告警管理

### 2.1 告警规则（6 条）

| 规则 | 级别 | 条件 | 通知方式 |
|------|------|------|---------|
| RAG 失败率 | critical | > 10% | 站内 + webhook |
| RAG P95 延迟 | warning | > 3s | 站内 |
| LLM 失败率 | critical | > 15% | 站内 + webhook |
| Milvus 失败率 | critical | > 5% | 站内 + webhook |
| MySQL 失败率 | critical | > 5% | 站内 + webhook |
| 任务连续失败 | warning | >= 3 次 | 站内 |

### 2.2 告警处理

**接口**：
- `GET /api/alerts` — 告警列表（status/severity 过滤）
- `PUT /api/alerts/{id}/ack` — 确认告警

**前端页面**：/workbench/admin/alert（异常告警管理）

**处理流程**：
1. 告警触发 → 写入 alert_events 表 → 站内通知 + webhook
2. 运维人员查看告警页面 → 排查原因
3. 确认告警（ack）→ 记录确认人和时间
4. 修复问题 → 告警自动恢复（status=active → acked）

### 2.3 Webhook 通知

配置 `config/alert.yaml`：

```yaml
alert:
  webhook:
    enabled: true
    url: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"  # 企微
    # url: "https://oapi.dingtalk.com/robot/send?access_token=xxx"   # 钉钉
```

## 四、故障处理 Runbook

### 4.1 MySQL 连接失败

**症状**：API 返回 500，日志报 MySQL connection error

**排查**：
1. 检查 MySQL 是否运行：`docker compose -f docker-compose.dev.yml ps mysql`
2. 检查连接配置：`config/database.yaml`
3. 检查连接池是否耗尽：查看日志中 active connections

**处理**：
- MySQL 未运行：`docker compose -f docker-compose.dev.yml up -d mysql`
- 配置错误：修正 database.yaml 中的 host/port/user/password
- 连接池耗尽：重启后端服务

**降级**：DB 宕机时 JWT 鉴权退回硬编码 USERS 兜底，系统不锁死

### 4.2 Milvus 连接失败

**症状**：RAG 检索返回空结果，日志报 Milvus gRPC error

**排查**：
1. 检查 Milvus Lite 文件：`backend/data/milvus/` 目录是否存在
2. 检查 gRPC 连接：日志搜 `too_many_pings` 或 `connection refused`
3. 检查集合是否加载：`GET /api/system/status` 看 milvus 状态

**处理**：
- 文件不存在：重新运行 `python scripts/data/init_db.py`
- gRPC too_many_pings：已优化为 5 分钟 keepalive，如仍出现重启后端
- 集合未加载：重启后端服务（lifespan 会重新加载）

### 4.3 RAG 检索延迟高

**症状**：P95 延迟 > 3s，告警触发

**排查**：
1. 查看监控看板：RAG P95 延迟趋势
2. 检查 LLM 调用：standardize 是否耗时（DeepSeek API 延迟）
3. 检查 Milvus 查询：向量检索是否耗时
4. 检查 Reranker：模型是否加载

**处理**：
- LLM 延迟：检查 DeepSeek API 状态，考虑关闭 standardize（config/agent.yaml standardize_enabled=false）
- Milvus 延迟：检查数据量，考虑重建索引
- Reranker 延迟：检查 SiliconFlow API 响应时间，确认 key 未被限流

### 4.4 ASR 识别失败

**症状**：语音识别返回空或错误

**排查**：
1. 检查 ASR 健康：`GET /api/asr/health`（检查阿里云NLS API连通性）
2. 检查 `.env` 中阿里云NLS凭据：ALICLOUD_ASR_APP_KEY/ACCESS_KEY_ID/ACCESS_KEY_SECRET
3. 检查 Token 获取：查看日志中"阿里云NLS Token获取成功"
4. 检查音频格式：Int16 PCM 16kHz

**处理**：
- API连通失败：检查网络/防火墙，确认能访问 nls-gateway.cn-shanghai.aliyuncs.com
- Token获取失败：检查AccessKey是否有效，是否有NLS服务权限
- 热词表无效：检查 ALICLOUD_ASR_HOTWORDS_ID 是否在NLS控制台已创建
- 音频格式错误：前端重采样逻辑检查

### 4.5 定时任务失败

**症状**：scheduler_task_log 中 result 为 error

**排查**：
1. 查看调度日志：`GET /api/scheduler/logs`
2. 查看任务详情：日志中 task_name + error 信息
3. 检查依赖服务：MySQL/Milvus/LLM 是否可用

**处理**：
- 依赖服务不可用：先修复依赖服务
- 任务逻辑错误：查看具体 error 信息，修复代码
- 手动重跑：`POST /api/scheduler/trigger/{job_id}`

## 五、日常运维

### 5.1 日志查看

```bash
# 实时日志
tail -f backend/logs/etc_qa.log

# 错误日志
grep "ERROR" backend/logs/etc_qa.log | tail -100

# API 日志（通过接口）
GET /api/system/logs?lines=100&level=ERROR
```

### 5.2 数据库维护

```bash
# 初始化（测试环境）
python scripts/data/init_db.py test

# 初始化（开发环境）
python scripts/data/init_db.py dev

# 权限迁移
python scripts/data/migrate_permissions.py
```

### 5.3 模型与 API 管理

| 模型/服务 | 用途 | 方式 | 配置 |
|-----------|------|------|------|
| bge-large-zh-v1.5 | Embedding | SiliconFlow API | config/models.yaml + .env SILICONFLOW_API_KEYS |
| bge-reranker-v2-m3 | Reranker | SiliconFlow API | config/models.yaml + .env SILICONFLOW_API_KEYS |
| 阿里云NLS | ASR | 阿里云API | config/asr.yaml + .env ALICLOUD_ASR_* |

SiliconFlow API 多 key 负载均衡：最长空闲优先选 key，429/5xx 自动冷却 60s 切下一个。
阿里云NLS Token自动获取+缓存（aliyunsdkcore），热词表在NLS控制台配置。
