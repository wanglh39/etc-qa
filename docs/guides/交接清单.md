# 交接清单

## 项目概述

ETC客服QA智能检索系统，面向客服人员（不面向客户），核心功能：
1. 客服输入问题 → 语义检索 → 返回最匹配的答案话术
2. 未匹配的问题 → 提交工单 → 工单处理后入库知识库
3. 知识库管理：软删除、配置热更新、分类体系动态加载

## 关键注意事项

### 1. 环境搭建

- **必须用 uv 虚拟环境 `etc_qa`（Python 3.10）**
- Embedding/Reranker 通过 SiliconFlow API 调用，需在 .env 配置 SILICONFLOW_API_KEYS
- ASR 走阿里云NLS API，需在 .env 配置 ALICLOUD_ASR_APP_KEY/ACCESS_KEY_ID/ACCESS_KEY_SECRET/HOTWORDS_ID
- MySQL 需提前建好，端口 3306，用户 root，密码默认 123456
- 首次运行必须执行 `python scripts/data/init_db.py test` 建表+导入数据
- 首次运行必须执行 `python scripts/data/init_config.py test` 初始化业务配置

### 2. 配置体系

**三层配置，优先级：DB > YAML > 代码默认值**

- `config.yaml`：基础设施（MySQL地址/SiliconFlow API/端口/阈值），运维改
- `system_config`表：业务规则（关键词/正则/规则），通过API改，**热更新不用重启**
- `.env`：敏感信息（API Key/密码），不提交git

### 3. 数据一致性

- **qa_pairs(MySQL) 和 qa_vectors(Milvus) 通过 qa_id 关联**
- 新增知识必须双写（MySQL + Milvus）
- 软删除只改MySQL的status字段，Milvus通过 active_qa_ids 过滤

### 4. Milvus 注意事项

- 使用 Milvus Lite（本地文件），不需要 Docker
- pymilvus 版本锁定 3.0.0，必须单独装 milvus-lite>=3.0.0
- **必须先 load_collection() 才能 search/insert**

### 5. 测试运行

```bash
# 后端
cd backend
etc_qa/Scripts/python.exe -m pytest tests/ -q --ignore=tests/integration    # 单元测试
etc_qa/Scripts/python.exe -m pytest tests/integration/ -m integration -q     # 集成测试(需MySQL)
etc_qa/Scripts/python.exe -m pytest tests/benchmark/ --benchmark-only -q     # 性能测试

# 前端
cd frontend
npm run test:coverage    # 单元测试+覆盖率
npm run e2e              # E2E测试
npm run lint             # 代码检查
```

### 6. CI/CD

- 统一CI：`etc_qa/.github/workflows/ci.yml`（9个job）
- 提交前检查：后端pre-commit + 前端husky/lint-staged
- 覆盖率硬门槛：前后端均 80%

## 常见问题

| 问题 | 解决方案 |
|------|---------|
| 服务启动报"LLM未启用" | 检查 .env 中 DEEPSEEK_API_KEY 是否配置 |
| Milvus search 报错 | 确认已执行 init_db.py 建表+导入数据 |
| BM25结果包含已删除知识 | 重启服务（BM25索引启动时构建） |
| 改了config.yaml不生效 | 基础设施配置需重启；业务配置用API热更新 |
| Windows上Milvus drop失败 | 手动删除 data/milvus/ 下的 .db 文件夹 |
| 前端测试找不到组件 | 检查 tests/helpers/stubs.ts 是否有对应stub |
