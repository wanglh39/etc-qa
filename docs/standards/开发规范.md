# 开发规范

## 代码规范

### Python 风格
- 遵循 PEP 8
- 类型注解：所有函数参数和返回值必须加类型注解
- 命名：函数/变量用 snake_case，类用 PascalCase，常量用 UPPER_SNAKE_CASE
- 单文件不超过 300 行，超过则拆分

### 注释规范
- **不写废话注释**（如 `# 初始化变量`）
- 关键业务逻辑必须写注释说明"为什么"而不是"做了什么"
- 公开函数必须写 docstring（简述+参数+返回值）

### 配置规范
- **代码只写逻辑，不写数据**：所有会变的东西放 DB 或 config.yaml
- **禁止硬编码**：业务关键词、正则规则、阈值、路径等必须从 config_center 或 config.yaml 读取
- **新增配置项**：同时在 config.yaml（兜底）和 system_config 表（热更新）中维护

### 数据库规范
- 表名 snake_case 复数（qa_pairs, work_orders）
- 字段名 snake_case
- 必须有 created_at + updated_at
- 软删除用 status 字段，不用物理删除
- SQL 语句中表名/字段名不硬编码在多处，集中在 mysql_client.py

### 测试规范
- 测试目录镜像源码目录结构
- 每个源文件必须有对应测试文件
- Mock 外部依赖（MySQL、Milvus、LLM），测试不依赖真实服务
- 后端运行：`etc_qa/Scripts/python.exe -m pytest tests/ -q`
- 前端运行：`npm run test`（vitest）
- 前端类型检查：`npx vue-tsc --noEmit`
- 前端 E2E：`npx playwright test`
- CI：`.github/workflows/ci.yml`（9 个 job：后端lint/测试 → 前端lint/测试/类型检查 → E2E → 契约 → 基准 → 构建）

## Git 规范

### 分支策略

```
main          ← 生产分支，保护分支
  ├── dev     ← 开发分支，日常开发合并到这里
  │   ├── feat/xxx   ← 功能分支
  │   ├── fix/xxx    ← 修复分支
  │   └── refactor/xxx  ← 重构分支
  └── test    ← 测试环境分支
```

### 提交信息格式

```
<type>(<scope>): <subject>

<body>
```

**type：**

| 类型 | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复bug |
| refactor | 重构（不改变功能） |
| docs | 文档 |
| test | 测试 |
| chore | 构建/配置/依赖 |

**scope：** 影响范围（rag/agent/db/api/config/scripts）

**示例：**

```
feat(agent): 合并structure_ingest和classify为一步LLM调用

- 一次LLM调用输出完整JSON含category_l1/l2
- ingest_agent从4步变3步
- 删除classify.py
```

### 提交前检查

1. `etc_qa/Scripts/python.exe -m pytest tests/ -q` 全部通过
2. 无硬编码的业务数据
3. 新增配置项已同步到 config.yaml 和 system_config
4. 改了项目结构要同步更新 目录结构.md 和 架构图.md

## 前后端对接规范

### API 约定
- 基础路径：`/api`
- 请求/响应统一 JSON
- 错误响应格式：`{"detail": "错误描述"}`
- 时间格式：ISO 8601（`2024-01-01T00:00:00`）
- 认证：JWT Bearer Token，Header 携带 `Authorization: Bearer <token>`

### 状态码

| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证或 token 失效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 429 | 请求限流 |
| 500 | 服务未初始化/内部错误 |

### 角色权限规范

5 角色 RBAC：superadmin / admin / ops / service / dept

- 后端：`require_role("admin", "superadmin")` 装饰器声明端点权限
- 前端：路由 `meta: { roleAuth: 'admin,ops' }` 声明页面权限
- superadmin 可访问所有页面（路由守卫直接放行）
- 前后端权限必须一致：前端 roleAuth 放行的角色，后端 require_role 也必须放行

### 新增接口流程
1. 在 `models/schemas.py` 定义请求/响应模型
2. 在 `api/routes.py` 实现路由
3. 在 `tests/api/test_routes.py` 写测试
4. 更新 `API接口文档.md`

每次修改项目结构后，**必须同步更新以下文件**：
1. `目录结构.md` — 目录树 + 调用关系
2. `架构图.md` — 架构图 + 链路说明

## 环境规范

### 环境变量
- 敏感信息（API Key、密码）放 `.env`，不提交 git
- `.env.example` 必须维护，列出所有环境变量及说明
- config.yaml 中敏感值用 `${ENV_VAR:default}` 语法

### uv 虚拟环境
- 环境名：`etc_qa`
- Python 版本：3.10
- 解释器路径：`etc_qa/Scripts/python.exe`（workdir=`backend/`）
- 新增依赖必须更新 `requirements.txt`
