# 交接清单

## 项目概述

ETC客服QA智能检索系统，面向客服人员（不面向客户），核心功能：
1. 客服输入问题 → 语义检索 → 返回最匹配的答案话术
2. 未匹配的问题 → 提交工单 → 工单处理后入库知识库
3. 知识库管理：软删除、配置热更新、分类体系动态加载

## 关键注意事项

### 1. 环境搭建

- **必须用 conda 环境 `etc_qa`（Python 3.10）**
- 模型文件路径在 config.yaml 中配置，首次需下载 bge-large-zh-v1.5 + bge-reranker-large
- MySQL 需提前建好，端口 3306，用户 root，密码默认 123456
- 首次运行必须执行 `python scripts/data/init_db.py test` 建表+导入数据
- 首次运行必须执行 `python scripts/data/init_config.py test` 初始化业务配置

### 2. 配置体系（重要！）

**三层配置，优先级：DB > YAML > 代码默认值**

- `config.yaml`：只存基础设施（MySQL地址/模型路径/端口/阈值），运维改
- `system_config`表：存业务规则（关键词/正则/规则），通过管理API改，**热更新不用重启**
- `.env`：存敏感信息（API Key/密码），不提交git

**改配置的正确姿势：**
- 改MySQL地址/模型路径 → 改 config.yaml → 重启服务
- 改关键词/正则规则 → 调 PUT /api/v1/config/{key} → 自动生效，不用重启
- 改API Key → 改 .env → 重启服务

### 3. 数据一致性

- **qa_pairs(MySQL) 和 qa_vectors(Milvus) 通过 qa_id 关联**
- 新增知识必须双写（MySQL + Milvus），用 `scripts/data/batch_import.py` 有一致性校验
- 软删除只改MySQL的status字段，Milvus通过 active_qa_ids 过滤，不物理删除向量
- BM25索引是启动时从MySQL构建的，软删除后需重启才能生效（待优化）

### 4. Milvus 注意事项

- 使用 Milvus Lite（本地文件），不需要 Docker
- pymilvus 版本锁定 3.0.0，必须单独装 milvus-lite>=3.0.0
- **必须先 load_collection() 才能 search/insert**（pymilvus 3.0.0 要求）
- Windows 上 drop_collection 有文件重命名bug，需手动删除数据库文件夹
- 批量插入太快会触发 gRPC too_many_pings，每批后关连接+延时3秒

### 5. LLM 调用

- 使用 DeepSeek API，Key 在 .env 中配置
- temperature=0.1, max_tokens=1024（可在 config.yaml 调整）
- structure_ingest 一次LLM调用输出完整JSON（含分类），不分开调用
- LLM改写可能产生幻觉，有后处理校验自动回退

### 6. 测试

- 211个测试全部通过，Mock了所有外部依赖
- 运行：`python -m pytest tests/ -q`
- 测试不依赖真实MySQL/Milvus/LLM，可离线运行

### 7. 评估脚本

- `eval_rag.py`：4配置消融对比，需本地运行（依赖真实MySQL+Milvus+模型）
- `eval_structure_ingest.py`：入库改写质量评估，需本地运行
- `eval_prompt_diff.py`：黄金数据集评估+DIFF对比，需本地运行
- 输出目录：`output/`

### 8. Docker部署

- `docker compose up -d` 一键启动
- MySQL用Docker容器，Milvus仍用Lite模式（.db文件）
- 生产环境MySQL host在config/database.yaml中配置为`mysql`（Docker网络名）

## 常见问题

| 问题 | 解决方案 |
|------|---------|
| 服务启动报"LLM未启用" | 检查 .env 中 DEEPSEEK_API_KEY 是否配置 |
| Milvus search 报错 | 确认已执行 init_db.py 建表+导入数据 |
| BM25结果包含已删除知识 | 重启服务（BM25索引启动时构建） |
| 改了config.yaml不生效 | 基础设施配置需重启；业务配置用API热更新 |
| Windows上Milvus drop失败 | 手动删除 data/milvus/ 下的 .db 文件夹 |
| conda run吞输出 | 长运行脚本建议写文件输出 |
