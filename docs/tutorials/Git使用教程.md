# Git 使用教程

## 一、核心概念

Git 有 3 个区域，理解这个就理解了 Git：

```
工作区（你写的代码）  → 暂存区（选好要提交的）  → 仓库（提交记录）
      git add              git commit
```

类比：**写作 → 装进书包 → 交给老师**

- **工作区**：你平时编辑代码的地方，改了还没标记
- **暂存区**：你选好"这次要提交哪些改动"的地方
- **仓库**：每次提交的快照记录，可以随时回退

## 二、VS Code 图形界面操作

### 2.1 打开 Git 面板

左侧栏第 3 个图标（分支形状），点击后看到：

```
┌─────────────────────────────────────────┐
│ 提交信息输入框          │ ← 在这里写提交信息
│ [提交] 按钮             │ ← 点这个提交
├─────────────────────────────────────────┤
│ 更改 (3)               │ ← 改了但没暂存的文件
│   📄 routes.py    M     │ ← M = 修改
│   📄 test.py      A     │ ← A = 新增
│   📄 old.py       D     │ ← D = 删除
├─────────────────────────────────────────┤
│ 暂存的更改 (2)          │ ← 已暂存，准备提交
│   📄 main.py      M     │
│   📄 config.yaml  M     │
└─────────────────────────────────────────┘
```

### 2.2 暂存文件（git add）

| 操作 | 方法 |
|------|------|
| 暂存单个文件 | 点文件名旁的 **"+"** |
| 暂存全部文件 | 点"更改"旁的 **"+"** |
| 取消暂存 | 点暂存区文件旁的 **"-"** |

### 2.3 提交（git commit）

1. 在顶部输入框**写提交信息**（必须写！不写提交不了）
2. 点**"提交"** 按钮，或按 `Ctrl + Enter`

**提交信息写什么？** 简单一句话说明改了什么：
- ✅ `修复routes.py的KeyError`
- ✅ `添加Docker开发环境`
- ✅ `集成测试覆盖率提升到84%`
- ❌ `update`（太模糊）
- ❌ 空着不写（提交不了）

### 2.4 推送到 GitHub（git push）

提交后代码还在本地，要推到 GitHub 队友才能看到：
- 左下角状态栏点**"同步更改"**（云朵↑图标）
- 或点 `...` 菜单 → **推送**

### 2.5 拉取队友代码（git pull）

- 点 `...` 菜单 → **拉取**
- 或左下角状态栏点**"同步更改"**（会同时拉取+推送）

### 2.6 查看历史记录

- 点 `...` 菜单 → **打开 Git 历史记录**
- 或安装扩展"Git Graph"（推荐，可视化分支图）

## 三、命令行操作

### 3.1 日常使用（90% 场景就这 3 条）

```bash
git add .                    # 暂存所有改动
git commit -m "改了什么"      # 提交
git push                     # 推到 GitHub
```

队友改了代码后：
```bash
git pull                     # 拉取最新代码
```

### 3.2 完整命令参考

| 操作 | 命令 | 说明 |
|------|------|------|
| **查看状态** | `git status` | 哪些文件改了、哪些已暂存 |
| **暂存单个** | `git add routes.py` | 只暂存这一个文件 |
| **暂存全部** | `git add .` | 暂存所有改动 |
| **取消暂存** | `git reset routes.py` | 把文件从暂存区移回工作区 |
| **提交** | `git commit -m "修复bug"` | 必须写提交信息 |
| **修改上次提交** | `git commit --amend -m "新信息"` | 上次提交写错了可以改 |
| **查看历史** | `git log --oneline` | 简洁版提交记录 |
| **推送** | `git push` | 推到 GitHub |
| **拉取** | `git pull` | 拉队友的最新代码 |
| **克隆** | `git clone <地址>` | 首次下载项目 |
| **查看差异** | `git diff` | 看具体改了什么内容 |

### 3.3 VS Code 操作与命令行对照

| VS Code 操作 | 等价命令 |
|-------------|---------|
| 点文件旁的"+" | `git add 文件名` |
| 点"更改"旁的 "+" | `git add .` |
| 点暂存区文件旁的 "-" | `git reset 文件名` |
| 输入框写信息 → 点提交 | `git commit -m "信息"` |
| 点"同步更改" | `git pull && git push` |
| 点 `...` → 推送 | `git push` |
| 点 `...` → 拉取 | `git pull` |

## 四、远程仓库（GitHub）

### 4.1 为什么要远程仓库？

```
没有远程仓库：代码只在你电脑上 → 换电脑就没了，队友拿不到
有远程仓库：  代码在GitHub上  → 随时随地访问，队友协作
```

### 4.2 首次关联远程仓库

1. 在 GitHub 网站上新建仓库（New Repository）
2. **不要**勾选"Add a README"（已有项目的话）
3. 复制仓库地址，在终端运行：
```bash
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin master
```

### 4.3 队友首次获取项目

```bash
git clone https://github.com/你的用户名/仓库名.git
cd 仓库名
```

## 五、常见问题

### Q: 提交后发现写错了提交信息？
```bash
git commit --amend -m "正确的提交信息"
```

### Q: 改了代码但想撤销？
```bash
git checkout -- routes.py    # 撤销单个文件的修改（恢复到上次提交的状态）
```

### Q: 暂存了但不想提交了？
```bash
git reset routes.py          # 从暂存区移出，文件改动还在
```

### Q: 想看某次提交改了什么？
```bash
git log --oneline            # 先找到提交的哈希值，如 abc1234
git show abc1234             # 查看那次提交的具体改动
```

### Q: push 被拒绝（队友先推了代码）？
```bash
git pull                     # 先拉取队友的代码
git push                     # 再推送
```

### Q: .env 文件不小心提交了？
```bash
# 从仓库中删除但保留本地文件
git rm --cached .env
git commit -m "移除.env文件"
# 确保 .gitignore 中有 .env
```
