# ETC客服QA智能检索系统 — 架构图

## 核心流程

```
客服来电 → 语音识别 → 流式过滤 → RAG检索 → 给客服候选提示 → 客服审核后回电
                                    │
                                    ├─ 命中 → 返回候选答案给客服看
                                    └─ 未命中 → 提交工单 → 工单处理 → 拉取已处理工单
                                                                    │
                                                                    └─ Agent入库预处理 → 入库
```

## 启动流程（企业级 lifespan 管理）

```
python main.py
    │
    ├─ 主进程执行 main.py 顶层代码
    │   ├─ load_dotenv()
    │   ├─ setup_logging()
    │   ├─ check_password_policy()
    │   ├─ 创建 FastAPI app（注册 lifespan）
    │   └─ uvicorn.run("main:app", reload=true)
    │
    └─ uvicorn 启动
        ├─ 主进程 (Reloader)
        │   └─ 只监控文件变化，不触发 lifespan
        │
        └─ fork 子进程 (Server)
            └─ lifespan startup 触发
                ├─ create_service()
                │   ├─ 加载配置 + 校验
                │   ├─ torch.set_num_threads(1)
                │   ├─ 加载 Embedding 模型 (GPU)
                │   ├─ 加载 Reranker 模型 (GPU)
                │   ├─ 初始化 MySQL 连接
                │   ├─ 初始化 MilvusQA
                │   ├─ 构建 BM25 索引
                │   ├─ 初始化召回/阈值/Reranker/QA服务
                │   ├─ FileLock 进程锁
                │   │   └─ RAG 预热（首次查询触发 Milvus load_collection）
                │   └─ ASR 预热（如启用）
                │
                ├─ 接受请求 → 推理
                │
                └─ lifespan shutdown
                    └─ 关闭 Milvus 连接，释放资源
```

## 检索链路（/api/query）

```
客服输入原始问题
    │
    ├─ Agent 标准化（2步）
    │   ├─ clean_text：防御性清洗（空格/标点/数字格式+工单前缀）
    │   └─ standardize_query：规则清洗 + LLM判断工具（保留品牌名/场景词）
    │
    ├─ RAG 检索
    │   ├─ Embedding编码（bge-large-zh-v1.5, 1024维）
    │   ├─ 获取 active_qa_ids（MySQL WHERE status='active'）
    │   ├─ 双路并行召回（ThreadPoolExecutor max_workers=2）
    │   │   ├─ 向量召回：Milvus余弦相似度，Top-10
    │   │   └─ BM25召回：jieba分词 + BM25Okapi，Top-10
    │   ├─ RRF合并（k=60），去重合并中每一个候选
    │   ├─ Reranker精排（bge-reranker-large），按分数重排
    │   └─ 阈值判定（gap差值模式）
    │       ├─ 差值=Top1分数-Top2分数
    │       ├─ 高置信：差值≥0.15且Top1≥0.5 → 返回Top-3
    │       ├─ 中置信：差值≥0.08且Top1≥0.3 → 返回Top-5
    │       ├─ 低置信：差值≥0.03且Top1≥0.15 → 返回Top-10
    │       └─ 无匹配：不满足以上 → 返回Top-10标记none
    │
    └─ MySQL补全记录 → 返回结果给客服
```

## 入库链路（/api/agent/process）

```
工单原始数据（问题+答案，格式因人而异）
    │
    ├─ clean_text（防御性清洗）
    ├─ 合并多余空格
    ├─ 去除标点冗余
    ├─ 数字分隔符修正 + 工单前缀清洗
    │
    ├─ structure_ingest（入库前标准化）
    │   ├─ 提示词渲染：PromptEngine从.j2文件加载 + jinja2渲染
    │   ├─ 结构化输出：LLM返回Pydantic Schema，字段静默校验
    │   ├─ 问题改写：工单描述→知识库标准格式（5-30字，提问式）
    │   ├─ 答案结构化：拆分文本→answer+internal_process+feedback_dept
    │   ├─ 分类匹配：从知识库分类体系选取category_l1/category_l2
    │   └─ 分类置信度：输出confidence，低于阈值标记needs_review
    │
    └─ 双库写入（MySQL + Milvus + HyDE向量）
       └─ Milvus写入失败：重试2次 → 仍失败则回滚MySQL(delete_qa) → 抛异常，保证双库一致
```

## WebSocket 流式链路（/ws/asr/stream）

```
前端建立WebSocket连接
    │
    ├─ 状态机：IDLE → LISTENING
    │
    ├─ 实时音频帧流入
    │   └─ VAD静音检测（numpy能量VAD，min_silence_ms=200）
    │       ├─ 有语音：累积音频
    │       └─ 静音触发：
    │           ├─ Fun-ASR-Nano离线识别
    │           ├─ 6层过滤
    │           │   ├─ 空句过滤
    │           │   ├─ 阈值过滤（字符数<2）
    │           │   ├─ 说话人过滤（跳过客服）
    │           │   ├─ 标点去重
    │           │   ├─ 纯指令静默（reset/select_answer）
    │           │   └─ 指令消息
    │           ├─ 纠错表应用（"E T C"→"ETC"等）
    │           ├─ RAG检索 → 推送候选结果
    │           └─ 状态机：LISTENING → QUERY_READY → CANDIDATES_SHOWN
    │
    └─ 控制消息
        ├─ select_answer → RESOLVED
        └─ reset → IDLE
```
